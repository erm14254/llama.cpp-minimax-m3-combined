Captured on the Blackwell machine with the frozen v4 runtime, torch
2.13.0+cu132, transformers 5.15.0, `sdpa`, `lsa_mode = full-owner`. All three
frozen gates cleared byte-exact, including `2e9b65eb…`.

Verified on arrival, 13/13 against `SHA256SUMS.txt`, every surface on the exact
BF16 lattice, and independently cross-checked by reconstructing
`bf16(frozen_input + o_proj[-1])` back to `2e9b65eb…` byte-exact — a check that
does not rely on the capture script's own self-report.

### Hardware, not library version, explains the Ampere miss

On the RTX 3090 the same harness clears gates 1 and 2 byte-exact and misses
gate 3 by ~1 BF16 ULP (rel-RMSE 0.00172, cosine 0.9999985, 2464/3072 elements
bit-identical). transformers **5.14.1 and 5.15.0 produce byte-identical output**
there, so the library version is excluded. torch, CUDA, weights, input and norm
are all identical. Remaining variable: Ampere vs Blackwell cuBLAS BF16 kernel
selection.

The C++ side shows the same signature: `inp_embd_ngram` and
`logical0_attn0_norm` reproduce byte-exact on Ampere, `logical0_attn0_resid`
does not (`88defe30…` vs frozen `2c804a35…`).

## Indicative localization — NOT authoritative

From the local Ampere C++ run, which **failed the Phase 3a gate**. Recorded
because the signal sizes are informative, and because it tells the Blackwell run
what to look for. It must not be cited as the parity conclusion.

Environment noise floor for reference: rel-RMSE **0.00172**.

| Surface | rel-RMSE | exact after BF16 round | reading |
|---|---|---|---|
| `q_a_proj` | 2.0e-06 | ~100% | exact |
| `q_a_layernorm` | **0** | **byte-exact** | exact |
| `q_b_proj` | 6.2e-06 | 99.89% | exact |
| `kv_a_proj_with_mqa` | 1.2e-03 | **99.31%** | missing BF16 boundary only |
| `kv_a_layernorm` | 1.6e-03 | 45.61% | below noise floor — needs Blackwell |
| `o_proj` | **1.95e-02** | **12.54%** | **real divergence** |

Three readings, with their robustness stated:

1. **The Q path is faithful.** `q_a_layernorm` is byte-exact to the Blackwell HF
   oracle (both `956bd3e8…`), so the existing Q-BF16 diagnostic is doing its
   job. Robust — three orders below the noise floor. This reframes the
   memorandum's "Q-BF16 made things worse": it made Q correct, while the
   dominant error sits downstream.
2. **`kv_a_proj_with_mqa` is arithmetically correct.** C++ computes it in F32
   where HF is BF16; rounding the C++ output to BF16 recovers 99.31% byte
   identity. Robust — 60× below the noise floor.
3. **`o_proj` is the dominant divergence.** rel-RMSE 0.0195, about 11× the noise
   floor, and BF16 rounding does *not* explain it (0.0196 before, 0.0196
   after). Its magnitude tracks the known `attn0_resid` rel-RMSE of
   0.0146–0.0152. Robust in direction.

`kv_a_layernorm`'s residual sits **below** the noise floor and is the one
reading that genuinely requires Blackwell before anything is concluded from it.

This points after `kv_a_layernorm`: RoPE, the MLA absorption (llama.cpp folds
`wk_b` into `q_nope` where HF does not), the attention kernel, or `wo`. That is
the branch the memorandum's interpretation table already anticipated.

**No arithmetic has been changed. No precision boundary has been patched.**

### Two findings embedded in the code

**`kqv_out-0` is the wrong `o_proj` boundary.** `build_attn` emits `kqv_out`
*before* applying `wo`, so it is 4096-wide pre-projection output while HF
`o_proj` is 3072-wide. A new `attn_out-0` callback marks the post-`wo`,
pre-residual surface.

**A ggml eval-callback `false` return does not abort a graph.** It breaks only
the current split's node loop while the enclosing loop continues, and it skips
the remainder of that split — so anything dumped afterwards is silently computed
from incomplete state. An early-abort hook was attempted, found to be doing
nothing while logging that it had stopped evaluation, and removed with the
reason documented in `common/debug.cpp`.
